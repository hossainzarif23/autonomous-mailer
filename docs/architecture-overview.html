System architecture overview

Autonomous Email Agent

A split-stack Gmail assistant where the browser stays thin, FastAPI owns all privileged work, LangGraph coordinates research and drafting, and every final email send pauses for human approval.

Architectural invariants

These rules are the stable mental model for contributors.

Backend is the trust boundary OAuth, Gmail tokens, LLM calls, persistence, and sending stay server-side.
Auth is cookie-based The frontend sends credentials automatically and never stores bearer tokens.
Sending requires approval send_email is interrupted, persisted as a draft, then resumed after review.

Business Context

The product turns a Gmail inbox into a conversational workflow for reading, researching, drafting, and safely sending email.

System Context

A C4-style container view: the frontend talks only to FastAPI; FastAPI owns every external integration and persistence boundary.

Client Backend processing External service Persistence

The browser receives an httpOnly access_token cookie from the backend OAuth callback. After that, credentialed REST, request-scoped chat streaming, and long-lived notification streaming all pass through FastAPI.

Processing Pipeline

A chat turn is a resumable LangGraph run. The conversation ID is the coordinator thread ID; specialized sub-agents keep user-scoped context.

Approval Loop

The most important runtime flow is the human-in-the-loop send boundary. It prevents non-idempotent Gmail sends before review.

Approve and edit decisions resume the same checkpoint and allow Gmail send. Reject decisions mark the draft rejected and return feedback to the coordinator; fresh-email rejection feedback can trigger another research-and-draft pass.

System Layers

The codebase is easier to navigate when viewed as four responsibility layers instead of a long file tree.

Client Next.js dashboard

App Router pages, route guards, chat UI, approval modal, Zustand stores, Axios REST client, raw chat stream parser, and EventSource notifications.

frontend/app frontend/components frontend/hooks frontend/stores

API FastAPI service

Cookie auth, CORS, REST/SSE routers, request validation, ownership checks, uniform error envelopes, and the only browser-facing backend contracts.

/api/auth /api/chat /api/approve /api/notifications

Agents LangGraph runtime

Coordinator and user-scoped specialist agents call Gmail, Tavily, and draft tools. Postgres checkpoints preserve conversations and approval interrupts.

coordinator mail_reader web_search mailing_agent

Data Postgres + external APIs

App tables store users, conversations, drafts, and notifications. Gmail tokens are encrypted. LangGraph checkpoint tables share the same database.

users conversations email_drafts notifications

Feature Surface

Authentication Google OAuth callback stores encrypted tokens and sets an httpOnly JWT cookie.
Conversation UI Structured blocks render markdown, status, email cards, summaries, research notes, and drafts.
Agent work LangGraph coordinates Gmail reads, web research, draft generation, and resumable approvals.
Notifications Approval, send, rejection, and error events are persisted and streamed to the dashboard.

Deployment Shape

Frontend Next.js 14 app server with NEXT_PUBLIC_API_URL pointing at the backend API prefix.
Backend FastAPI on Python 3.11+, started with uvicorn app.main:app.
Database One Postgres database, two DSN styles: async SQLAlchemy and psycopg/LangGraph.
Scaling caveat Live notification queues are in-memory and per-process; use shared pub/sub before horizontal scaling.

Quality Drivers

These are the constraints that shape the architecture more than any individual framework choice.

Security

Browser never receives Gmail tokens; protected resources are scoped by authenticated user ownership.

Safety

Final Gmail send is approval-gated and persisted as a draft before any side effect.

Recoverability

LangGraph checkpoints allow approval decisions to resume after the original chat request ends.

Maintainability

Backend emits typed content blocks so the frontend renders semantics instead of parsing tool text.
