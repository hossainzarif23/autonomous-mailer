Autonomous Email Agent — Architecture Overview

Full-stack Gmail assistant: Google OAuth · FastAPI · LangChain/LangGraph agents · human-in-the-loop approval · Next.js dashboard

This is the system-level visual overview. For per-package implementation detail see backend/docs/architecture.md and frontend/docs/architecture.md.

Business Context

Objective

Turn a Gmail inbox into a conversational agent that reads, researches, drafts, and sends mail — with a human gate before any send.

Users

Single end-user (personal Google account). Each user owns their own conversation history, drafts, and notifications.

Value

Reduces inbox triage to one chat turn. Agent summarizes threads, researches unfamiliar topics, drafts context-aware replies, and pauses for a single approval click.

Key Metrics

  • Time-to-draft per thread
  • Approval pass-rate (approve vs edit vs reject)
  • Token / OpenRouter cost per turn

Data Flow

Client / data store Backend / processing LLM / search External API auth flow (dashed)

Cookie-based auth: the browser hits Google OAuth, the callback lands on FastAPI which sets an httpOnly access_token JWT cookie. All subsequent REST + SSE calls carry the cookie automatically.

Processing Pipeline — Chat Turn

Token stream flows back to the browser over the same SSE connection (/api/chat/message). The coordinator thread ID = conversation_id; sub-agents run on user-scoped threads (mail_reader_{user_id}, web_search_{user_id}, mailing_agent_{user_id}).

Human-in-the-Loop Approval Loop

The send_email tool is the approval boundary. On resume, needs_research_refresh is set when a fresh draft is rejected with research cues — the coordinator re-runs research before re-drafting.

System Architecture Layers

Data Layer — Postgres (one DB, two persistence layers)

usersconversationsemail_draftsnotifications

App tables managed by Alembic / SQLAlchemy 2.0 async (asyncpg). LangGraph checkpoint tables managed automatically by AsyncPostgresSaver.setup() at startup. Same DB, two DSNs: DATABASE_URL (asyncpg) for ORM, DATABASE_URL_PSYCOPG for checkpoints + Alembic.

Processing Layer — LangGraph Agent Graph

Coordinator (thread = conversation_id) delegates to user-scoped sub-agents:

  • mail_reader_{user_id} — read-only Gmail tools
  • mailing_agent_{user_id} — strict JSON draft
  • web_search_{user_id} — Tavily research

State carries current_draft, research_summary, draft_feedback, needs_research_refresh. Checkpointed after every step.

Services Layer — FastAPI Routers

/api/auth/api/chat/api/emails/api/approve/api/notifications

Cookie auth via get_current_user (JWT decode, not bearer). Two SSE streams: request-scoped chat (/chat/message) and long-lived notifications (/notifications/stream). HITL resume lives in /approve/{draft_id}.

Output Layer — Client UI

dashboardConversationSidebarChatWindowApprovalModalSSE toasts

Next.js 14 App Router, Zustand stores (auth / chat / approval), hand-rolled SSE parser for chat, native EventSource for notifications. Structured content_blocks render markdown / status / tool_action / email_list / summary / research_report / draft_email.

Features

Functional

  • Google OAuth + Gmail scopes
  • Read / search / summarize threads
  • Draft fresh mail + replies
  • Pre-draft web research
  • HITL approve / edit / reject
  • Live chat + notification SSE
  • Conversation history

Non-Functional

  • Cookie auth — no bearer tokens
  • Fernet-encrypted Gmail tokens at rest
  • Token auto-refresh < 5 min from expiry
  • Per-user SSE broadcast isolation
  • Checkpointed = resumable agent state
  • Strict TS, Pydantic v2 validation

Cross-Cutting

  • Uniform error shape {error, detail}
  • Axios 401 → auto redirect /login
  • Edge middleware guards /dashboard
  • @lru_cache LLM + checkpointer singletons

Deployment

Model

Split-stack monorepo. Backend (FastAPI) and frontend (Next.js) run as two independent services — no shared package manager. CORS ties them: backend allows FRONTEND_URL only.

Prerequisites

  • Postgres with pgcrypto ext
  • Google OAuth client (gmail scopes)
  • OpenRouter API key
  • Tavily API key
  • Fernet + JWT secrets

Backend Workflow

  • pip install -r requirements.txt
  • alembic upgrade head
  • uvicorn app.main:app --reload

Frontend Workflow

  • npm install
  • npm run dev / npm run build
