Agentic Pipeline · Deep Dive

The AI Agentic Pipeline
behind the Autonomous Email Agent

A multi-agent system built on LangChain create_agent + LangGraph, orchestrated by a coordinator that routes intent to specialized sub-agents, calls tools against Gmail and the web, and pauses at the final send_email step for native human-in-the-loop approval. State is checkpointed in Postgres so any graph — including interrupted ones — can resume.

02Agents & their responsibilities

Every agent is its own create_agent-compiled graph. The coordinator exposes them as async callable tools and shares one AgentContext per request.

Coordinator

Routes intent · owns the thread

The brain. Interprets the user prompt, decides which sub-agent (or tools) to call, asks for clarification when intent is ambiguous, and stitches the final answer.

  • Built with create_agent + context_schema=AgentContext
  • Tools: call_mail_reader_agent, call_mailing_agent, call_web_search_agent, ask_for_clarification
  • thread_id = conversation_id → resumable after interrupt
Mail Reader

Read · search · summarize

Talks to Gmail only. Returns structured content blocks (email_list, summary) so the UI can render cards instead of a wall of text.

  • Tools: list_recent_emails, search_emails, get_email, summarize_thread
  • User-scoped thread_id — isolated from coordinator thread
  • Never sends — safe to invoke without approval
Mailing

Draft-only · owns the HITL gate

Composes fresh emails and replies. The only path to send_email — and the only place that calls LangGraph interrupt() for human approval.

  • Tool: draft_email (writes DB row) + send_email (interrupts)
  • Always persists draft before pausing — UI has something to show
  • Resumes via Command(resume=...) with approve / edit / reject payload
Web Search

Research before drafting

Optional pre-step for fresh-email flows. Pulls web sources via Tavily so drafts aren't pulled out of thin air.

  • Tool: tavily_search(query) via direct TavilyClient (not the LangChain wrapper)
  • Returns a research_report content block for the chat UI
  • Called by coordinator before call_mailing_agent for fresh-email prompts
HITL gate

The approval boundary

Not an agent — a behavior of the mailing agent's send_email tool. This is the only irreversible action in the system, so it always pauses for the user.

  • Native LangGraph interrupt({...}) — graph checkpoints and stops
  • Resume: Command(resume={"approved": bool, "edited_body": ...})
  • Approved → Gmail send. Rejected → coordinator can rewrite the draft.
Shared services

One context, many tools

All agents share a per-request AgentContext that wraps the heavy services. No closures, no global state — context is injected by the runtime.

  • GmailService — async Gmail API client, token refresh
  • NotificationService — per-user SSE queue + persisted notifs
  • AsyncPostgresSaver — LangGraph checkpointer (separate DSN)

05State, context & persistence

Two persistence layers, one database, one thread model — and a per-request context object that travels into every tool call.

AgentContext

Per-request dependency injection

Built once per request, injected via LangChain's context_schema + ToolRuntime. No closures, no globals — every tool reads from runtime.context.

# backend/app/agents/context.py
class AgentContext(BaseModel):
    user: User
    conversation: Conversation
    gmail: GmailService
    db: AsyncSession
    notifications: NotificationService
    checkpointer: AsyncPostgresSaver
Two persistence layers · one DB

App tables + LangGraph checkpointer

SQLAlchemy (async) manages the app domain. LangGraph writes its own checkpoint tables to the same Postgres using the psycopg DSN.

06Three pipeline variants

The same wiring handles three different user intents — read, reply, and fresh email — with the HITL gate only on the write paths.

1

Read flow no send

User: "Summarize emails from BRAC Bank this week." Coordinator → mail reader → tools → SSE cards back to chat. No draft, no interrupt.

2

Reply flow HITL

User: "Reply to the last email from hr@… with a polite decline." Coordinator → mail reader (find target) → mailing (draft) → interrupt → resume → send.

3

Fresh email flow HITL

User: "Write to ceo@… about AI trends in Bangladesh." Coordinator → web search (research) → mailing (draft) → interrupt → resume → send. Rejection may re-trigger research.

4

Clarification safe

User: "Send her something nice." Coordinator can't resolve "her" or "something nice" → ask_for_clarification → SSE question → user clarifies → loop.

07The LLM ↔ tools loop

Inside any agent, this loop repeats until the model emits a final answer or hits an interrupt. The checkpointer makes every step reproducible and replayable.

Per-step behavior
state.messages grows on every turn · interrupt persists and yields control to the API
graph cycle 
# 1. user message enters the coordinator graph
state.messages.append(HumanMessage(prompt))

# 2. LLM decides: answer now OR call tools
response = ChatOpenRouter(model="qwen/qwen3.5-35b-a3b").bind_tools(tools).invoke(state.messages)

# 3. if tool calls → execute them in parallel, append ToolMessages
for call in response.tool_calls:
    result = execute_tool(call.name, call.args, runtime=ToolRuntime(context))
    state.messages.append(ToolMessage(content=result, tool_call_id=call.id))

# 4. special-case: send_email → interrupt() yields the graph
if call.name == "send_email":
    approval = interrupt({draft_id, to, subject, body})   # pauses · checkpointed

# 5. resume (Command(resume={approved, edited_body})) continues from step 3
if approval["approved"]:
    gmail.send_email(draft)        # external side effect
    notifications.emit("email_sent", draft)

# 6. LLM summarises outcome · final assistant message appended · graph ends
state.messages.append(AIMessage("Sent. Confirmation: ..."))

08Design principles in one glance

Why the pipeline is shaped the way it is — the rules that keep the agents safe, resumable, and observable.

HITL

One irreversible action, one gate

send_email is the only tool that touches the outside world in a non-reversible way. Everything else is read or local DB. The gate is always interrupt(), never a UI prompt the backend has to trust.

Stateful

Threads are first-class

thread_id = conversation_id. The checkpointer turns every graph run into a durable object that can be replayed, time-travelled, or resumed after a user closes the tab.

Composable

Sub-agents are tools

Each sub-agent is a compiled graph, exposed to the coordinator as an async tool. The coordinator doesn't know — or care — which model the sub-agent uses, only what it returns.

Single owner

One coordinator per turn

The coordinator is the only agent that talks to the user. Sub-agents return structured content blocks; the coordinator composes them into the final answer.

Fresh when needed

Research is opt-in

Web search is called by the coordinator only for fresh-email workflows. Read and reply flows skip it entirely, keeping latency and cost low.

Observable

Every step is a stream

SSE carries tool calls, content blocks, and interrupts. LangGraph checkpoints add a second observability layer. LangSmith tracing is a one-flag opt-in.
